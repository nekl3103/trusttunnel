# TrustTunnel для OpenWrt

[English](README.en.md) · [Релизы](https://github.com/nekl3103/trusttunnel/releases) · [Установка на другой роутер](INSTALL-OTHER-ROUTER.ru.md) · [Ошибки](https://github.com/nekl3103/trusttunnel/issues)

TrustTunnel на роутере с управлением через LuCI: несколько VPN-серверов, отдельный выход для каждой группы сайтов и правила для устройств домашней сети. VPN-клиент на телефоне, телевизоре или компьютере не требуется.

Этот репозиторий содержит нашу OpenWrt-интеграцию: пакет `luci-app-trusttunnel`, установщик, маршрутизацию, управление клиентами и тесты. Сам VPN-клиент устанавливается из проекта [TrustTunnelClient](https://github.com/TrustTunnel/TrustTunnelClient). Сервер TrustTunnel настраивается отдельно.

## Что реализовано

- **Несколько серверов.** Добавление и импорт конфигурации, включая `tt://`-ссылки; отдельный процесс клиента, TUN-интерфейс и таблица маршрутизации для каждого включённого сервера. HTTP/2 и HTTP/3 (QUIC), параметры TLS и закрепление PEM-сертификата.
- **Группы сайтов из Geosite.** Каталог `v2fly/domain-list-community`, добавление нужных категорий, дополнительные домены и автоматическое обновление списков. В настройках отображаются выбранные группы; полный каталог загружается по запросу и кешируется.
- **Выбор сервера для каждой группы.** Фиксированный сервер, автоматический выбор из пула, основной с резервными или распределение групп между доступными серверами. Критерии автоматического выбора: задержка, скорость или надёжность.
- **Маршрутизация по устройствам.** Назначение групп по IP-адресу, подсети или MAC-адресу. При включении этого режима через VPN идут только назначенные устройствам группы; остальной трафик остаётся прямым.
- **Контроль соединения.** Проверки сервера и туннеля, контрольные URL групп, подтверждение повторных ошибок, порог и пауза между автоматическими переключениями. При стабильной работе проверки выполняются реже; замеры скорости — отдельно, не чаще одного раза в 30 минут.
- **Управление в LuCI.** Состояние серверов и маршрутов групп, ручное переключение выхода, журнал клиента, запуск, остановка и обновление списков. Длительные операции выполняются в фоне с защитой от одновременного запуска.
- **DNS и nftables.** IPv4/IPv6, выборочная маршрутизация через DNS-наборы, исключения, killswitch, настройки DNS и DoH. Изменение маршрутов групп применяется атомарно без очистки уже наполненных наборов адресов.
- **Диагностика.** Проверка конфигурации и доменов, сравнение прямого и туннельного внешних IP, измерение скорости и задержки.
- **Сохранение настроек.** Конфигурация защищена при обновлении APK; пароли многосерверных профилей хранятся отдельно в файлах с доступом только владельцу.

Списки `itdoginfo/allow-domains`, собственные домены и подсети также поддерживаются в генераторах и UCI-конфигурации. Основной интерфейс настройки групп использует Geosite.

## Установка

Нужны OpenWrt **25.12+**, LuCI, пакетный менеджер `apk`, доступ по SSH и конфигурация своего сервера TrustTunnel. Поддерживаемые архитектуры клиента: `aarch64`/`arm64`, `armv7l`/`armv8l`, `mips`, `mipsel`, `x86_64`. OpenWrt с `opkg` установщик не поддерживает.

Выполните на роутере:

```sh
sh -c "$(wget -O - https://raw.githubusercontent.com/nekl3103/trusttunnel/main/install.sh)"
```

Установщик скачивает **последний опубликованный релиз** пакета и клиент TrustTunnel. Изменения, находящиеся только в ветке `main`, попадут в такую установку после выпуска нового релиза.

Для маршрутизации доменов требуется `dnsmasq-full` с `nftset`. Если штатный `dnsmasq` собран без этой поддержки, установщик предложит замену. Она перезапускает DNS. После первой установки сначала настройте серверы и группы.

## Настройка через LuCI

1. Откройте **Службы → TrustTunnel → Настройки**.
2. На вкладке **Серверы** добавьте сервер, задайте название и нажмите **Импорт…** в его форме. Вставьте конфигурацию или `tt://`-ссылку либо заполните параметры вручную. Добавьте остальные серверы при необходимости.
3. На вкладке **Группы сайтов** нажмите **Показать каталог групп**, выберите категорию и **Добавить группу**. Например: `youtube`, `telegram`, `openai`.
4. Для каждой группы выберите выход: конкретный сервер или автоматическую стратегию. В **Параметрах** задайте пул, основной сервер, критерий выбора, контрольный URL и дополнительные домены.
5. Сохраните и примените настройки. На вкладке **Общее** включите запуск при загрузке, если он нужен; на странице **Состояние** запустите службу.
6. Проверьте состояния серверов и выбранные выходы групп. На странице **Диагностика** проверьте домен и внешний IP.

Пример назначения:

| Группа | Выход |
|---|---|
| YouTube | Автоматический выбор из двух серверов |
| Telegram | Конкретный сервер |
| ChatGPT / OpenAI | Основной сервер с резервным |

Чтобы настроить доступ отдельно для телевизора, телефона или компьютера, сначала сохраните группы, затем добавьте устройство на вкладке **Устройства**, укажите IP, подсеть или MAC и назначьте группы. Включите **Маршрутизацию по устройствам** на вкладке **Общее** и примените настройки.

## Режимы маршрутизации

| Режим | Трафик через VPN |
|---|---|
| Выборочный | Домены и подсети выбранных групп, с учётом исключений и правил устройств |
| Всё через VPN | Интернет-трафик LAN с учётом настроенных исключений |

Трафик самого роутера включается отдельной настройкой. Killswitch блокирует выбранный трафик при отсутствии туннеля, если включён.

Сопоставление доменов зависит от DNS роутера. Собственный DoH/DoT на устройстве может обходить его; сайты с общими IP могут попадать под одно правило. Правила Geosite `regexp` и `keyword` не поддерживаются: интерфейс показывает число пропущенных правил. Для `full` используется доменное сопоставление dnsmasq, которое также охватывает поддомены.

Каждый активный сервер запускает отдельный клиент и расходует память. Гостевые сети нужно явно добавить в список LAN-интерфейсов.

## Проверки и сборка

Shell-тесты запускаются в Linux:

```sh
sh tests/run.sh
```

GitHub Actions проверяет тесты, права исполняемых файлов, ShellCheck **0.11.0**, синтаксис shell, JavaScript, JSON и ucode, а также импорты модулей LuCI и ucode. Среда CI закреплена на Ubuntu 24.04.

Workflow **Release** собирает APK через OpenWrt SDK для `x86-64-25.12.5`. Пакет LuCI имеет архитектуру `all`; бинарник VPN-клиента устанавливается отдельно под архитектуру роутера. Сборка сохраняет основной пакет и русский перевод в артефактах; push тега `v*` также публикует их в GitHub Releases.
