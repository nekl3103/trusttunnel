# TrustTunnel для OpenWrt

[English](README.en.md) · [Скачать APK](https://github.com/nekl3103/trusttunnel/releases/latest) · [Установка на другой роутер](INSTALL-OTHER-ROUTER.ru.md) · [Ошибки](https://github.com/nekl3103/trusttunnel/issues)

Управление TrustTunnel на роутере через LuCI. Можно подключить несколько серверов, выбрать выход для каждой группы сайтов и назначить группы отдельным устройствам домашней сети. Телефонам, телевизорам и компьютерам отдельный VPN-клиент не нужен.

Репозиторий содержит пакет `luci-app-trusttunnel`, русский перевод, установщик, маршрутизацию и управление клиентами. Бинарник клиента устанавливается отдельно из [TrustTunnelClient](https://github.com/TrustTunnel/TrustTunnelClient) под архитектуру роутера. Собственный сервер TrustTunnel и его конфигурация должны быть подготовлены заранее.

## Установка на OpenWrt

### Требования

- OpenWrt **25.12 или новее**, пакетный менеджер **`apk`** и LuCI.
- Доступ по SSH от пользователя `root` и доступ роутера к GitHub и репозиториям OpenWrt.
- Архитектура клиента: `aarch64` / `arm64`, `armv7l` / `armv8l`, `mips`, `mipsel` или `x86_64`.
- Устройство TUN и `dnsmasq-full` с поддержкой `nftset` для маршрутизации групп сайтов. Установщик устанавливает зависимости и предлагает замену обычного dnsmasq при необходимости.
- Свободное место для клиента и списков. Каждый включённый сервер запускает отдельный процесс и дополнительно расходует оперативную память.

OpenWrt с `opkg` и штатные прошивки производителей этим установщиком не поддерживаются. Пакеты LuCI имеют архитектуру `all`; архитектурные ограничения относятся к бинарнику клиента.

### Автоматическая установка

Подключитесь к роутеру с компьютера. Замените адрес, если ваш роутер использует другой:

```sh
ssh root@192.168.1.1
```

Проверьте версию OpenWrt и архитектуру:

```sh
cat /etc/openwrt_release
uname -m
command -v apk
df -h /overlay
```

Затем **на роутере** скачайте и запустите установщик:

```sh
wget -O /tmp/trusttunnel-install.sh https://raw.githubusercontent.com/nekl3103/trusttunnel/main/install.sh && sh /tmp/trusttunnel-install.sh
```

Установщик:

1. Проверяет систему и архитектуру, устанавливает зависимости.
2. Предлагает заменить dnsmasq без `nftset` на `dnsmasq-full`. Для групп сайтов согласитесь на замену; DNS кратковременно перезапустится.
3. Скачивает основной APK и русский перевод из **последнего опубликованного релиза**.
4. Устанавливает клиент TrustTunnel под архитектуру роутера.
5. Обновляет backend LuCI и возвращает ранее работавшую службу в рабочее состояние.

После первой установки настройте хотя бы один включённый сервер и одну включённую группу сайтов, затем запустите службу.

### Первичная настройка в LuCI

1. Откройте **Службы → TrustTunnel → Настройки**.
2. На вкладке **Серверы** нажмите **Добавить сервер**. Задайте название, откройте **Импорт…** и вставьте конфигурацию сервера или ссылку `tt://`. Параметры можно заполнить вручную. Сохраните и примените настройки.
3. На вкладке **Группы сайтов** откройте каталог, выберите категорию и добавьте группу. Например: `youtube`, `telegram`, `openai`.
4. Выберите для группы автоматический выбор сервера, основной с резервными, распределение между серверами или конкретный сервер. Укажите пул серверов и при необходимости дополнительные домены.
5. На вкладке **Общее** включите **Запуск при загрузке**, сохраните и примените настройки. На странице **Состояние** запустите её, если она ещё остановлена.
6. На странице **Состояние** проверьте доступность серверов и фактический выход каждой группы.

Чтобы маршрутизировать группы только для выбранных устройств, добавьте их на вкладке **Устройства**, задайте IP-адрес, подсеть или MAC и назначьте группы. Затем включите **Маршрутизацию по устройствам**. Без этого режима группы действуют для настроенных LAN-интерфейсов в целом. Гостевые сети добавляются в список LAN-интерфейсов отдельно.

## Как работают серверы и группы

- Для каждого включённого сервера создаются отдельный клиент, TUN-интерфейс и таблица маршрутизации. Поддерживаются HTTP/2, HTTP/3 (QUIC), параметры TLS и PEM-сертификаты.
- Группы используют каталог [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community). Можно добавить собственные домены, изменить группу, отключить или удалить её. Каталог кешируется, списки обновляются автоматически.
- Автоматические стратегии выбирают доступный сервер из пула по задержке, скорости или надёжности. Приоритетная стратегия использует основной сервер с резервными; распределение назначает группы разным доступным серверам.
- **Новый сервер при сохранении добавляется в пулы существующих групп.** Закреплённый вручную выход группы сохраняется.
- **Удалённый сервер отвязывается от групп**, включая пул и основной сервер. Если группа была закреплена за ним, она переходит на автоматический выбор.
- **Недоступный сервер исключается после неудачной проверки** и снова допускается после успешной. Проверка действует также для закреплённого сервера и временного выбора. Автоматическая группа может выбрать другой доступный сервер из своего пула.
- Если для группы нет доступного выхода, её распознанный трафик блокируется. Закреплённый или временно выбранный недоступный сервер не заменяется другим автоматически.

На странице **Состояние** можно выбрать сервер для группы и нажать **Применить на 30 мин**. Это временный выбор: после окончания срока группа возвращается к сохранённой стратегии. Изменение настроек маршрута группы также отменяет прежний временный выбор.

Проверяются соединение с сервером, трафик через туннель и контрольный URL группы. HTTP `401`, `403` и `429` отображаются как ограничения доступа к сайту; такой ответ сам по себе не означает отказ туннеля. Повторные ошибки контрольного сайта учитываются отдельно для соответствующей группы.

## DNS и маршрутизация

Текущий интерфейс настройки использует **многосерверную выборочную маршрутизацию по группам**. Не входящий в группы трафик остаётся прямым, с учётом правил устройств и исключений. Прежний односерверный режим и режим «всё через VPN» остаются в backend и UCI; инструкции для них находятся в подробном руководстве.

Dnsmasq получает IP-адреса доменов и добавляет их в наборы nftables. Правила направляют эти адреса через выбранный сервер группы. Поддерживаются IPv4 и IPv6.

- Устройства должны использовать DNS роутера. Собственный DoH/DoT или другой DNS на устройстве может обходить сопоставление доменов.
- При смене сервера группы меняется маршрут; перезапуск DNS для такого переключения не требуется.
- При полном перезапуске TT правила DNS загружаются повторно через перезапуск dnsmasq. Отметка об их загрузке сохраняется только после успешного перезапуска.
- Изменение правил групп применяется атомарно. Неизменённые наборы адресов сохраняются, удалённые правила очищаются только у затронутых групп.
- Домены с общими IP могут попадать под одно правило. Geosite-правила `regexp` и `keyword` пропускаются; интерфейс показывает их количество. Точное доменное правило `full` сопоставляется средствами dnsmasq и также охватывает поддомены.

Списки `itdoginfo/allow-domains`, собственные домены и подсети поддерживаются генераторами и UCI-конфигурацией. Основной интерфейс групп использует Geosite.

## Обновление и ручная установка APK

Для обычного обновления повторно запустите автоматический установщик. Настройки `/etc/config/trusttunnel` защищены при обновлении пакета. Пароли многосерверных профилей хранятся отдельно в `/etc/trusttunnel/secrets` с доступом только владельцу.

Изменения в ветке `main` не обновляют APK автоматически: установщик берёт пакет из опубликованного релиза. Сам установщик скачивается из `main`.

Если клиент и зависимости уже установлены, APK можно обновить вручную. Скачайте **оба пакета и `SHA256SUMS`** со страницы [последнего релиза](https://github.com/nekl3103/trusttunnel/releases/latest). В каталоге скачанных файлов на Linux проверьте суммы:

```sh
sha256sum -c SHA256SUMS
```

Скопируйте APK с компьютера на роутер:

```sh
scp -O luci-app-trusttunnel-*.apk luci-i18n-trusttunnel-ru-*.apk root@192.168.1.1:/tmp/
```

На роутере выполните команды ниже. В `/tmp` должна находиться только одна версия каждого APK:

```sh
/etc/init.d/trusttunnel stop
apk add --allow-untrusted /tmp/luci-app-trusttunnel-*.apk
apk add --force-reinstall --force-overwrite --allow-untrusted /tmp/luci-i18n-trusttunnel-ru-*.apk
rm -f /tmp/luci-indexcache
/etc/init.d/rpcd restart
/etc/init.d/trusttunnel start
```

Флаги установки перевода позволяют обновиться со старого пакета `luci-i18n-trusttunnel-direct-ru`, который использовал тот же файл локализации, и повторить частично завершённую установку. APK устанавливаются с `--allow-untrusted`, поскольку не подписаны ключом репозитория пакетов OpenWrt.

## Проверка после установки

На роутере:

```sh
/etc/init.d/trusttunnel running && echo SERVICE_OK
cat /var/etc/trusttunnel/multi/health.tsv
cat /var/etc/trusttunnel/multi/selection.tsv
nslookup www.youtube.com 127.0.0.1
nft list set inet trusttunnel_multi g_youtube4
logread -e trusttunnel | tail -50
```

Последние две проверки YouTube применимы, если добавлена группа с UCI-идентификатором `youtube`. У других групп наборы имеют собственные имена; всю таблицу можно посмотреть через `nft list table inet trusttunnel_multi`.

На странице **Диагностика** доступны проверки домена, внешнего IP, скорости и задержки. Длительные операции службы выполняются в фоне; состояние операции и результат отображаются в LuCI.

Если раздел TrustTunnel не появился, очистите кеш LuCI командами выше и обновите страницу браузера без кеша. Если сервер доступен, а сайт не открывается, проверьте DNS устройства, выбранный выход группы, её адресные наборы и журнал.

## Проверки проекта и документация

GitHub Actions запускает регрессионные тесты, проверяет исполняемые права, ShellCheck **0.11.0**, синтаксис shell, JavaScript, JSON и ucode, а также импорты модулей LuCI. Сборка релиза выполняется в OpenWrt SDK и публикует основной APK, русский перевод и `SHA256SUMS`.

Для запуска тестов в Linux:

```sh
sh tests/run.sh
```

Часть проверок требует Node.js или ucode; при их отсутствии соответствующие тесты отмечаются как пропущенные. В CI эти проверки выполняются отдельно.

Релиз `v1.1.0` / `1.1.0-r18` проверен установкой опубликованных APK на реальном роутере OpenWrt **25.12.5**: конфигурация сохранена, три сервера запущены, адресные наборы YouTube заполнены и HTTPS через выбранный туннель работает. Это проверка одного роутера, а не всех поддерживаемых архитектур.
